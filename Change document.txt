You are a senior enterprise product architect, UX strategist, content strategist, and full-stack implementation lead working on an Agentic AI-based Regulatory Reporting platform for banks.

Your task is to redesign and implement the Data Foundation page of the product so that it follows the same upgraded UI/UX principles, visual density, hierarchy, polish, and enterprise-grade audit-oriented design language already applied to the revised home page.

The current Data Foundation page has these broad sections:

Page title and description

Reporting period selector

Tabs such as Source Systems / Canonical Elements / Rule Engine

A main working panel with a table/grid

A side sign-off queue panel

The redesign must preserve the product’s premium regulatory reporting feel, but make the page much more business-friendly, CFO-ready, operationally clear, and aligned to how report data is actually prepared and signed off.

Core objective
Reframe the Data Foundation page from a vague technical setup page into a business-ready report data preparation workflow.

The page should clearly communicate this end-to-end flow:

Data ingestion → Data validation → Rule engine → Report-ready data elements → Maker submission → Checker sign-off → Go to Report Pack

Everything before Maker submission should be system-driven / automated.
Maker and Checker should only operate on the final report-ready data elements stage.
No manual override of data element values is allowed.

Mandatory product and UX changes
1. Apply the same new homepage design principles
Use the exact same improved design principles and visual system that were applied to the updated home page:

denser and cleaner layout

stronger hierarchy

less empty space

premium enterprise look

audit-focused and operational

more polished cards, headers, tables, and navigation

clearer labels, reduced vagueness

Do not leave the page looking like a generic SaaS admin screen.

2. Replace vague terminology
The current language is too vague and too internal.

Replace “Canonical Elements”

Replace any wording that sounds abstract, technical, or architecture-led rather than business-led

The replacement terminology should communicate:

Provide better naming options and choose the best one in the UI. Preferred direction:

7. No data overwrite by Maker or Checker
This is critical.

There should be no manual override allowed by Maker or Checker on the report data element values.
Remove any current override-oriented behavior in the grid.

That means:

no editable override column

no freeze / reopen / manual overwrite flow for values

no “maker edits certified numbers directly” pattern

Instead:

upstream ingestion and rule processing generate the report-ready data elements

Maker reviews and submits the report-ready data elements

Checker reviews and signs off

values themselves are not manually overwritten in this stage

If adjustment logic is needed, it should happen through either:

corrected ingestion data

modified rule parameters in the Rule Engine

or a governed re-run of the workflow

Make this explicit in both product logic and UI text.

there is no sign-off on modified rules themselves
